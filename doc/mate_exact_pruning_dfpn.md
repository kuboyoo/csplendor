# 厳密な枝刈りとDFPNの検証（2026-09-07）

## 結果と範囲

対象は `bga_910749228.kifu` の50手終了後、P0が51手目を選ぶ局面。
入力は `tests/fixtures/mate_routes_bga_910749228_ply50.spn`。
P0の合法手78通り、すべての合法な応手・未確定の補充を対象とする。
棋譜に記録された未来の山札順には固定しない。

| P0の残り行動回数 | 結果 | 探索ノード | 実時間 |
| --- | --- | ---: | ---: |
| 6 | 全78初手で6回以内の詰みなし | 20,612,409 | 約40.9秒 |
| 7 | 全78初手で7回以内の詰みなし | 11,931,700 | 約93.2秒 |
| 8 | 全78初手で8回以内の詰みなし | 11,886,848 | 約153.8秒 |

それぞれ独立したC++の単一スレッド探索。ノード上限は0（無制限）。
開発中の比較計測は一部同時実行しており、時間は負荷と環境に依存する。
各結果で `unknown_reason=null`、`root_actions_completed=root_actions=78` を確認した。
前版は6回・600秒（4並列）でも未確定だった。
浅い深さでは期限による反証、深い深さでは終局による反証が増えるため、
深さとノード数は単調にはならない。深いルート評価自体の費用も異なる。

今回確認したのは **指定回数以内の確定勝ちがないこと**。
無期限の不詰み、P1の全補充に対する確定勝ち、実際の対局でのP0敗北とは異なる。
候補限定探索の失敗や時間切れを、不詰みと読み替えていない。

## 数学的に枝を省略する条件

### 得点の楽観的上界

残り2〜3行動について、攻撃側に実際より有利な条件を与える。
残りの全カードを直ちに入手可能・再購入可能とし、非購入の1行動につき
ワイルドトークン3枚を最初から与え、銀行残数と10枚制限を無視する。
色別トークンは購入後も残すが、緩和した合計財布から割引後価格を減らす。
貴族も最後の割引で獲得可能なものを、残り行動回数まで楽観的に加算する。

実際の購入手順はこの緩和に含まれるので、ここでも15点に届かなければ
指定回数以内の勝ちは不可能。一方、15点に届いても詰みの証明にはならない。
上界計算の内部予算を使い切った場合も「到達可能かもしれない」として通常探索へ戻る。
この内部予算は探索全体のノード上限ではない。

### 妨害できない次の応手

P0の次の1行動による最良結果を、得点と購入枚数の辞書式順序で上から評価する。
P1の予約カードに、その最良結果以上で15点以上になる購入があれば、
P0はそのカードを奪えず、次のP1手番で終局させられる。
同じ条件を満たす場のカードが異なる2枚ある場合も、P0は一度に1枚しか除けない。

P1の得点の下界には、P0がどの合法購入・非購入でも先に取れそうな貴族を含めない。
これにより、貴族の横取り・同点・購入枚数による逆転を誤って省略しない。
判定は実際の補充を反映した局面で行う。仮の補充での同じ評価は順序付けにしか使わない。

### 反証の再利用

場札、予約札、貴族の並び順だけが違う局面は正規化して扱う。
予約カードと非公開フラグは組で並べ替え、支払モードの違いは区別する。
終局等から導いた「深さに依存しない反証」と、手数上限だけによる反証を分離する。
後者をより深い探索へ流用しない。

また、攻撃側のトークンと銀行残数を無視したキーで、反証に有効だった応手・補充を
**順序のヒントとしてだけ**再利用する。現局面での合法性を再確認し、
証明用キャッシュには完全なルール局面のキーを使う。ヒントの衝突・不適合で枝を削らない。
この再利用が、返却トークンだけ違う局面での反証探索の繰り返しを大幅に減らした。

別途、守備側と補充だけを1候補に制限した短い予備探索も行う。
攻撃側は全合法手を残すので、この簡単なゲームで負ければ本探索の反証になる。
予備探索の勝ちは本探索の証明に混ぜず、全応手・全補充の検証に戻る。

## DFPNをどう適用したか

Splendorの確定勝ちも有限深さのAND/OR問題として表現できる。
攻撃側の手はOR、相手の応手と不確定な補充はANDとなる。
証明数を `p`、反証数を `d` とすると、更新は次の通り。

| 節点 | p | d |
| --- | --- | --- |
| OR | 子のpの最小値 | 子のdの合計 |
| AND | 子のpの合計 | 子のdの最小値 |

`p=0` が詰み、`d=0` が指定深さでの不詰み。両方正なら未確定。
これは [van den Herik・WinandsによるPN/DFPNの解説](https://dke.maastrichtuniversity.nl/m.winands/documents/pnchapter.pdf)
のAND/OR証明数と深さ優先閾値探索に基づく。

C++に `use_dfpn=True` を追加した。閾値の拡大量は広い分岐への探索配分にだけ使い、
0による証明条件は変えない。残り3行動以下は既存の厳密探索で解く。
補充も具体化し、未完了の節点は証明済みキャッシュに入れない。
時間切れ・キャンセルは未確定のままとする。

既知の6回・7回の詰み、および独立した小局面の全列挙と一致した。
ただし開発中の本局面の深さ7では、DFPN版は180秒でも未確定だった。
枝の非常に広いゲームで、DFPNへの置換だけが高速化を保証するわけではない。
既定は今回結果が出た厳密DFS版とし、DFPNは比較用の明示オプションとする。
DFPNを使う条件は厳密・攻撃側全合法手・通常の全補充検証・DAG出力なし・
厳密な推奨手順固定なし。その他の組合せは従来の探索へフォールバックする。

## 再現と回帰検査

エンジンを使用するPythonプロセスを止めてからビルドする。
実行中に拡張モジュールを上書きしないこと。

```bash
python setup.py build_ext --inplace -j 4
PYTHONPATH=. python scripts/benchmark_mate_routes.py tests/fixtures/mate_routes_bga_910749228_ply50.spn --depth 6 --seconds 300
PYTHONPATH=. python scripts/benchmark_mate_routes.py tests/fixtures/mate_routes_bga_910749228_ply50.spn --depth 7 --seconds 300
PYTHONPATH=. python scripts/benchmark_mate_routes.py tests/fixtures/mate_routes_bga_910749228_ply50.spn --depth 8 --seconds 300
PYTHONPATH=. python scripts/benchmark_mate_routes.py tests/fixtures/mate_routes_bga_910749228_ply50.spn --depth 7 --seconds 180 --dfpn
python -m pytest tests/test_mate_route_ordering.py -m performance
```

従来の `--require-conclusion` は無期限の不詰みか詰みを要求するオプションなので、
今回の深さ以内の不詰みでは引き続き終了コード1となる。
深さ6〜8での完了条件は上記の `performance` テストで検査する。

通常のテストには、小局面の独立全列挙、貴族の横取り、予約による妨害、
同点の購入枚数比較、予備探索の誤った陽性の不採用、局面の非変更、
支払モードのキャッシュ分離、浅い不詰みの後に深い詰みが見つかる回帰を含む。

GUIの既存APIは既定の改善版を利用する。UI側にルール実装は追加していない。
ただしGUIは浅い深さから順に調べ、制限時間を全深さで共有するため、
上表の「深さ8だけを約154秒で調べる」計測とは別である。
GUIで120秒等を設定した場合に深さ8まで必ず完了する、という保証ではない。
