# Splendor 棋譜ファイル仕様 (.kifu)

**Version:** 1.1 Draft  
**Date:** 2026-10-05  
**依存仕様:** [USI.md](USI.md) — アクション記法・SPN盤面記法・宝石色記号

---

## 1. 概要

`.kifu` ファイルは Splendor の対局記録をテキスト形式で保存するためのファイルフォーマットである。
将棋の KIF/KI2/CSA 棋譜フォーマットを参考に、USI プロトコルのアクション記法 (USI Move Notation) および盤面記法 (SPN) と完全に互換性を持つよう設計されている。

### 1.1 設計原則

1. **人間可読性**: プレーンテキストで記述し、テキストエディタで直接閲覧・編集可能。
2. **USI 互換**: アクション表記は USI Move Notation をそのまま使用する。
3. **完全再現性**: 初期盤面 (SPN) + 手順で対局を完全に再現可能。
4. **拡張性**: メタデータヘッダにより任意の情報を付加可能。
5. **エンコーディング**: UTF-8。改行は `\n` (LF)。

---

## 2. ファイル構造

```
[ヘッダセクション]
（空行）
[盤面セクション]
（空行）
[手順セクション]
（空行）
[結果セクション]
```

各セクションは空行で区切る。

---

## 3. ヘッダセクション

`Key: Value` 形式のメタデータ行。順不同。

### 3.1 必須ヘッダ

| キー | 説明 | 例 |
|------|------|----|
| `Format` | ファイルフォーマット識別子 | `Splendor KIFU v1.1` |
| `Players` | プレイヤー数 | `2` |
| `Player0` | 先手プレイヤー名 | `Genbu v2.0` |
| `Player1` | 後手プレイヤー名 | `DeepSets v1.0` |

#### Format のバージョン

| 値 | 内容 |
|----|------|
| `Splendor KIFU v1.1` | 現行。山札予約後の返却は、同じプレイヤーの独立した `return:<C>` 手として記録する。csplendorの書き出しはこの値を使う |
| `Splendor KIFU v1.0` | 旧形式。山札予約の返却を `reserve:L2/return:W` の1手で記録する |

csplendorはv1.0も読み込める。読み込み時に旧来の1手表記 `reserve:L<n>/return:<C>`
（返却色1文字）を `reserve:L<n>` と `return:<C>` の2手に展開する。

### 3.2 省略可能ヘッダ

| キー | 説明 | 例 |
|------|------|----|
| `Date` | 対局日時 (ISO 8601) | `2026-02-11T21:00:00+09:00` |
| `Player2`, `Player3` | 3-4人戦時のプレイヤー名 | `Human` |
| `Event` | 大会・イベント名 | `AI Championship 2026` |
| `Round` | ラウンド番号 | `3` |
| `TimeControl` | 持ち時間。§5.4 | `150+30/150` |
| `Seed` | 乱数シード（再現用） | `42` |
| `Engine0` | P0 のエンジン情報 | `Genbu v2.0 (MCTS 1600)` |
| `Engine1` | P1 のエンジン情報 | `DeepSets v1.0 (MCTS 800)` |
| `Tags` | 自由タグ (カンマ区切り) | `distillation,test` |

## 4. 盤面セクション

初期盤面を SPN (Splendor Position Notation) で記述する。

```
Position: <SPN文字列>
```

または初期局面の場合:

```
Position: startpos 2
```

> [!NOTE]
> Splendor はカードの初期配置がランダムのため、`startpos` だけでは盤面を一意に決定できない。
> 再現性が必要な場合は `Seed` ヘッダ、または完全な SPN を使用すること。

詰み問題など、あとから同一局面を厳密に再現する必要がある KIFU では、
伏せ予約カードを `reserved:[?C86]` のように記録できる。`?C<id>` は
伏せ予約であることを示しつつ、再現用のカードIDも保持する。公開情報だけを
記録する `?L<level>` 形式はカードIDを持たないため、厳密な再現には使えない。
player section の `nobles:[<id>,...]` は取得済み貴族ID、`bought:[<id>,...]`
は購入済みカードIDを表す。カードIDが不明な購入済みカードは `_` で枚数だけを
表せるが、詰み問題などの再現用 SPN では実カードIDを保存する。

## 5. 手順セクション

1手ごとに1行。以下の書式:

```
<turn>. P<player> <usi_move> [<time_ms>] [# <comment>]
```

| フィールド | 説明 | 必須 |
|-----------|------|------|
| `<turn>` | 手番号（1始まり、全プレイヤー通し番号） | ○ |
| `P<player>` | プレイヤー番号 (P0, P1, ...) | ○ |
| `<usi_move>` | USI アクション記法 | ○ |
| `[<time_ms>]` | その決定のために時計から差し引いた時間（ミリ秒、角括弧で囲む）。§5.4 | 任意 |
| `[# <comment>]` | コメント（`#` 以降） | 任意 |

### 5.1 例

```
1. P0 take:WUG [2341]
2. P1 take:RKG [1520]
3. P0 take:RR [890]
4. P1 reserve:C71 [3200] # レベル3カードを確保
5. P0 buy:C27 [1100]
6. P1 take:WUK [950]
7. P0 buy:C2/gold:K1 [2800] # 金を黒に充当
8. P1 buy:C42 [1200]
```

### 5.2 貴族訪問の記録

手番の終わりに条件を満たす貴族が2枚以上あるとき、同じプレイヤーが選ぶ貴族を独立した手として記録する。
1枚だけなら自動で訪問するので、手は記録しない。

```
15. P0 buy:C84 [3500]
16. P0 noble:N3 [1200]
```

### 5.3 山札予約後の返却の記録

山札予約で所持トークンが11枚になった場合、同じプレイヤーがめくれたカードを見てから
1枚返す。返却は予約とは別の手として、同じプレイヤー番号で記録する。

```
21. P1 reserve:L2 [1800]
22. P1 return:W [400]
```

### 5.4 持ち時間と消費時間

`TimeControl` の値（`<tc>`）は次のいずれかである。

- `<初期秒>+<加算秒>/<上限秒>`: フィッシャー方式（上限なしは `<初期秒>+<加算秒>`）。
- `<秒>s/move`: 1手ごとの固定時間。毎手その秒数から始まり、残りは繰り越さない。
- `none`: 持ち時間なし（プレイヤー別の書式でのみ使う）。

両者が同じ `<tc>` なら `TimeControl: <tc>` と1つだけ書く。プレイヤーごとに違うときは、
空白で区切って `TimeControl: P0=<tc> P1=<tc>` と書く（3-4人戦は `P2=`、`P3=` も同様）。
全員が持ち時間なしならヘッダを省略する。一部だけなしなら、そのプレイヤーを `P<n>=none` と書く。

以下はフィッシャー方式のプレイヤーの規則である。時計は初期秒から始まり、
自分の手番の間だけ減る。手番の終わりに1回だけ加算秒を足し、上限秒を超えた分は切り捨てる。
時計が0になったプレイヤーの負けとする（`Result: P<相手>_WIN TIME`、§6）。

- `[<time_ms>]` は、その決定のために時計から差し引いた時間である。時計が動くのは、人間なら手番が回ってきた時点から、
  エンジンなら思考要求を受けた時点からで、前の手の確定後の通信や演出の時間は含めない。
- 返却（`return:`）と貴族選択（`noble:`）は手番を消費しない2段目の決定だが、それぞれに消費時間を記録する。
  加算は手番の最後の決定の後に1回だけ行う。
- 残り時間は `TimeControl` と各手の `[<time_ms>]` から再計算できるので、記録しない。

```
TimeControl: 150+30/150

21. P1 reserve:L2 [1800]    # P1 の時計から 1.8 秒
22. P1 return:W [400]       # 続けて 0.4 秒。手番の終わりに +30 秒（上限 150 秒）
```

人間（P0）が `150+30/150`、AI（P1）が1手5秒の例:

```
TimeControl: P0=150+30/150 P1=5s/move
```

`<秒>s/move` のプレイヤーは、1回の手番の決定（`return:` や `noble:` を含む）の消費時間の合計が
その秒数を超えたら時間切れとする。

公開予約・宝石取得の返却は従来どおり同じ手に含める（例: `reserve:C10/return:U`）。

### 5.5 パスの記録

```
20. P0 pass [0]
```

### 5.6 コメント専用行

手順とは独立して、コメント行を挿入できる。

```
# 中盤戦: P0がレベル3カードの購入を狙い始める
12. P0 reserve:C75 [4100]
```

## 6. 結果セクション

対局結果を記載する。

```
Result: <result_type> [<detail>]
```

| result_type | 説明 |
|------------|------|
| `P0_WIN` | P0 の勝利 |
| `P1_WIN` | P1 の勝利 |
| `DRAW` | 引き分け（同点 + 同カード枚数） |
| `ONGOING` | 未終局 |

| detail | 説明 |
|--------|------|
| （なし） | 通常の終局（または未終局） |
| `TIME` | 時間切れ。時計が0になったプレイヤーの相手の勝ち（例: `Result: P1_WIN TIME`） |

時間切れの棋譜では、時間切れの時点で確定していない決定だけを記録しない。同じ手番ですでに確定した決定は記録する
（例えば山札予約の後、返却を選んでいる間に時間切れになった場合は、山札予約までを記録し、棋譜は返却フェーズの局面で終わる）。
`FinalScores`・`TotalTurns` は時間切れの時点の値とする。

追加情報を同セクションに記載可能:

```
Result: P0_WIN
FinalScores: P0=16 P1=12
TotalTurns: 54
```

| キー | 説明 |
|------|------|
| `FinalScores` | 各プレイヤーの最終スコア |
| `TotalTurns` | 総手数 |
| `FinalCards` | 各プレイヤーの購入カード枚数 |

Engine0: Genbu v2.0 (MCTS 1600, cpuct=2.5)
Engine1: DeepSets v1.0 (MCTS 800, cpuct=2.5)

Position: bank:W4U4G4R4K4D5 | visible:L1[2,11,18,27]L2[41,49,53,60]L3[71,75,79,84] | decks:36,24,12 | nobles:[1,5,9] | P0:gems:W0U0G0R0K0D0;bonuses:W0U0G0R0K0;points:0;reserved:[];bought:[] | P1:gems:W0U0G0R0K0D0;bonuses:W0U0G0R0K0;points:0;reserved:[];bought:[] 0

## 8. バリエーション記法（解析用・拡張）

棋譜解析やAI間比較で、分岐手順を記録したい場合に使用する。

```
V{
  <分岐手順>
}
```

### 8.1 例

```
10. P1 take:RR [620]
V{
  # AI候補手2: 予約の方が評価値は高かった
  10. P1 reserve:C75 [620]
  11. P0 buy:C41 [1800]
}
11. P0 buy:C41 [1800]
```

## 9. AI 解析注釈（拡張）

各手に AI の評価情報を付加できる。`@` プレフィックスで記述する。

```
<turn>. P<player> <move> [<time>]
  @eval <winrate>
  @pv <move1> <move2> ...
  @policy <move1>:<prob1> <move2>:<prob2> ...
  @nodes <n>
```

### 9.1 例

```
7. P0 buy:C2/gold:K1 [2800]
  @eval 0.62
  @nodes 1600
  @pv buy:C2/gold:K1 take:WUG buy:C41
  @policy buy:C2/gold:K1:0.45 take:WUG:0.22 reserve:C75:0.18
```

## 10. パーサー実装ガイド

### 10.1 読み込み手順

```
1. UTF-8 テキストとして読み込み
2. 空行で3-4セクションに分割
3. ヘッダ: "Key: Value" を辞書にパース
4. 盤面: "Position:" 行から SPN をパース
5. 手順: 各行を正規表現で分解
6. 結果: "Result:" 行を result_type と detail（任意、例 `TIME`）に分けてパース
```

### 10.2 手順行の正規表現

```regex
^(\d+)\.\s+P(\d+)\s+(\S+)(?:\s+\[(\d+)\])?(?:\s+#\s*(.*))?$
```

| グループ | 内容 |
|---------|------|
| 1 | 手番号 |
| 2 | プレイヤー番号 |
| 3 | USI アクション文字列 |
| 4 | 思考時間 (ms)、省略可 |
| 5 | コメント、省略可 |

### 10.3 注釈行の正規表現

```regex
^\s+@(\w+)\s+(.+)$
```

## 11. 他フォーマットとの変換

| 変換元 | 変換先 | 方法 |
|--------|--------|------|
| `.pkl` (ori) | `.kifu` | `board_ori` を SPN に変換、ori アクションを USI 記法に変換 |
| `.kifu` | `.pkl` | USI 記法をパースし、csplendor Game で再生して各ステップの state を pickle |
| `.kifu` | JSON | 各フィールドを JSON オブジェクトにマッピング |
| BGA ログ | `.kifu` | BGA スクレイパーの出力を USI 記法に変換 |
